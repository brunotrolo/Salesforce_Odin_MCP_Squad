Odin
Capítulo 1 · A ideia

Um MCP para o time inteiro usar as mesmas skills

Hoje cada repositório carrega a sua cópia das skills. Com o Odin, todo mundo conecta o Claude Code num único servidor, que sabe quem está pedindo, escolhe a skill certa e entrega sempre a versão aprovada.

Cada projeto tem a própria cópia, e as versões se desencontram.

As 5 skills que entram no Odin

Um ciclo de entrega Salesforce, do discovery ao teste de tela.

Discovery-to-BacklogJourney DesignerJourney DeveloperData ArchitectTest Automator

Por que "Odin"

Na mitologia, Odin tem dois corvos: Huginn (pensamento) e Muninn (memória). Aqui, Huginn é o roteador que entende o pedido e escolhe a skill; Muninn é a base de conhecimento que lembra padrões e regras, com a fonte citada.

Capítulo 2 · O mapa

Três lugares, cada um com um papel

O GitHub guarda o conteúdo, o Google Cloud controla quem acessa o quê, e a máquina do dev executa o trabalho. Clique em qualquer bloco.

Capítulo 3 · Do GitHub ao Odin

Como uma versão nova de skill chega a todo mundo

Ninguém instala nada. O mantenedor muda a skill no GitHub; o pipeline valida, empacota e assina o pacote; o catálogo libera primeiro no canal beta e depois no stable.

"Crie a classe de teste do CaseRouter"

Capítulo 5 · Segurança e autenticação

  
Quem é você, o que pode usar e o que nunca acontece

  
Login com GitHub mais um segundo fator, uma credencial presa ao computador e um token que vive só 15 minutos e se renova sozinho. Na máquina, o guarda de segurança bloqueia ações perigosas, seja qual for a instrução recebida.

Padrões técnicos, regras de negócio e lições aprendidas entram por revisão humana e voltam nas respostas com a fonte. Cada cliente só vê o que é do seu projeto.
